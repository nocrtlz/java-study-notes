### 总结10个问题

1. Java 异常体系中 Checked 和 Unchecked 的区别？

   **Checked 异常在编译期强制你处理；Unchecked 异常编译期不管，运行期才可能抛出**

2. `finally` 中写 `return` 会发生什么？

   会 **覆盖 try 或 catch 中的返回值**，也会 **吞掉异常**。

3. `ArrayList` 和 `LinkedList` 的底层区别与适用场景？

   | 对比          | ArrayList              | LinkedList                               |
   | :------------ | :--------------------- | :--------------------------------------- |
   | 底层结构      | 动态数组               | 双向链表                                 |
   | 内存          | 连续内存，紧凑         | 节点分散，每个节点存前后指针，内存开销大 |
   | 随机访问      | O(1)                   | O(n)                                     |
   | 尾部添加      | 平均 O(1)，扩容时 O(n) | O(1)                                     |
   | 中间插入/删除 | O(n)，要移动元素       | 找到位置 O(n)，插入删除 O(1)             |
   | 扩容          | 默认 1.5 倍            | 不需要扩容                               |
   | 适用场景      | 读多写少，随机访问多   | 频繁头尾插入删除，作为队列/栈            |

   一句话：
   **ArrayList 适合查，LinkedList 适合头尾增删。**

4. `HashMap` 的底层结构、扩容机制、为什么线程不安全？

   ### 底层结构

   - JDK 8 之前：数组 + 链表。
   - JDK 8 及以后：数组 + 链表 + 红黑树。
   - 链表长度 `>= 8` 且数组长度 `>= 64`，链表转红黑树。
   - 红黑树节点数 `<= 6`，退化成链表。

   ### 扩容机制

   - 默认容量 `16`，负载因子 `0.75`。
   - 阈值 = 容量 × 负载因子。
   - 元素数量超过阈值，扩容为原来的 `2` 倍。
   - 扩容后重新计算索引：`e.hash & (newCap - 1)`。
   - 元素要么留在原索引，要么移到 `原索引 + oldCap`。

   ### 为什么线程不安全？

   1. **数据覆盖**：多线程同时 put，可能一个线程的写入被另一个覆盖。
   2. **size 计数不准**：`size++` 不是原子操作。
   3. **JDK 7 扩容死循环**：头插法在并发扩容时可能形成循环链表。
   4. **JDK 8 仍有数据丢失**：虽然修复了循环链表，但并发 put 仍可能丢失数据。
   5. **modCount 并发修改**：可能抛 `ConcurrentModificationException`。

   解决：用 `ConcurrentHashMap` 或 `Collections.synchronizedMap`。

5. `ConcurrentHashMap` 如何保证线程安全？

   ### JDK 7

   - 分段锁 `Segment`，继承 `ReentrantLock`。
   - 默认 16 个 Segment，每个 Segment 独立加锁。
   - 不同 Segment 可以并发写。

   ### JDK 8

   - 取消 Segment，改用 **CAS + synchronized**。
   - 底层：数组 + 链表 + 红黑树。
   - put 时：
     - 如果桶为空，用 CAS 插入头节点。
     - 如果桶不为空，用 `synchronized` 锁住桶的头节点。
   - 扩容：多线程协助迁移。
   - size：用 `CounterCell` 分散计数，类似 `LongAdder`。
   - 读操作不加锁，靠 `volatile` 保证可见性。

   特点：

   - 线程安全。
   - 不允许 `null` 键和 `null` 值。
   - 并发性能远高于 `Hashtable`。

6. JVM 运行时内存区域有哪些？堆和栈的区别？

   ### 运行时内存区域

   **线程私有：**

   1. 程序计数器：当前线程执行字节码的行号。
   2. 虚拟机栈：存栈帧，方法调用入栈，返回出栈。
   3. 本地方法栈：为 native 方法服务。

   **线程共享：**

   1. 堆：对象实例，GC 主要区域。
   2. 方法区：类元信息、常量、静态变量等。JDK 8 后用元空间实现。

   ### 堆和栈的区别

   | 对比     | 堆                 | 栈                             |
   | :------- | :----------------- | :----------------------------- |
   | 线程共享 | 共享               | 每个线程私有                   |
   | 存储内容 | 对象实例、数组     | 局部变量、操作数栈、方法出口等 |
   | 内存大小 | 大                 | 小                             |
   | 速度     | 慢                 | 快                             |
   | 回收     | GC 管理            | 方法结束自动释放               |
   | 异常     | `OutOfMemoryError` | `StackOverflowError`           |

7. 类加载过程与双亲委派模型是什么？

   ### 类加载过程

   1. **加载**：读取字节码，生成 `Class` 对象。
   2. **验证**：验证格式、语义、字节码、符号引用。
   3. **准备**：静态变量分配内存并设零值。
   4. **解析**：符号引用转直接引用。
   5. **初始化**：执行 `<clinit>`，静态变量赋值和静态代码块。

   之后是使用和卸载。

   ### 双亲委派模型

   类加载请求先交给父加载器，父加载器无法完成才自己加载。

   加载器层次：

   1. Bootstrap ClassLoader：加载 `JAVA_HOME/lib` 核心类。
   2. Extension / Platform ClassLoader：加载扩展类。
   3. Application ClassLoader：加载应用类路径。
   4. 自定义 ClassLoader。

   好处：

   - 安全：避免核心类被篡改。
   - 避免重复加载。

8. MySQL 为什么用 B+ 树做索引？聚簇索引和非聚簇索引区别？

   ### 为什么用 B+ 树？

   1. **树矮**：多路平衡树，磁盘 IO 少。
   2. **范围查询快**：叶子节点用双向链表连接。
   3. **查询稳定**：所有查询都要走到叶子节点。
   4. **非叶子只存键**：能存更多索引项，进一步降低树高。

   ### 聚簇索引 vs 非聚簇索引

   | 对比     | 聚簇索引        | 非聚簇索引（二级索引） |
   | :------- | :-------------- | :--------------------- |
   | 叶子节点 | 存整行数据      | 存主键值               |
   | 数量     | 一张表一个      | 可以有多个             |
   | 是否回表 | 不需要          | 通常需要回表           |
   | 代表     | InnoDB 主键索引 | 普通索引、唯一索引     |

   覆盖索引：查询列都在索引中，不需要回表。

9. 事务的 ACID 和隔离级别是什么？

   ### ACID

   1. **原子性 Atomicity**：事务要么全成功，要么全失败。
      实现：`undo log`。
   2. **一致性 Consistency**：数据从一个一致状态到另一个一致状态。
   3. **隔离性 Isolation**：并发事务互不干扰。
      实现：锁 + MVCC。
   4. **持久性 Durability**：提交后永久保存。
      实现：`redo log`。

   ### 隔离级别

   | 隔离级别 | 脏读   | 不可重复读 | 幻读            |
   | :------- | :----- | :--------- | :-------------- |
   | 读未提交 | 可能   | 可能       | 可能            |
   | 读已提交 | 不可能 | 可能       | 可能            |
   | 可重复读 | 不可能 | 不可能     | InnoDB 基本解决 |
   | 串行化   | 不可能 | 不可能     | 不可能          |

   MySQL 默认隔离级别：**可重复读**。
   InnoDB 通过 **MVCC + 间隙锁** 解决幻读。

10. 泛型擦除是什么？PECS 原则怎么用？

    ### 泛型擦除

    Java 泛型在编译后会被擦除：

    - `List<Integer>` 和 `List<String>` 运行时都是 `List`。
    - 泛型类型参数被替换为原始类型，如 `Object` 或限定类型。
    - 不能 `new T()`。
    - 不能 `instanceof List<Integer>`。
    - 不能创建泛型数组。
    - 编译器通过桥接方法保证多态。

    ### PECS 原则

    **Producer Extends, Consumer Super**

    - `? extends T`：上界通配符，适合读，不适合写。
      读出来是 `T`，不能 add（除 null）。
    - `? super T`：下界通配符，适合写，不适合读。
      能 add `T` 及其子类，读出来只能是 `Object`。

- Checked 编译期强制处理，Unchecked 不强制。
- finally 中 return 会覆盖返回值、吞异常，禁止使用。
- ArrayList 查快，LinkedList 头尾增删快。
- HashMap 数组+链表+红黑树，扩容 2 倍，线程不安全。
- ConcurrentHashMap 用 CAS + synchronized + 多线程协助扩容。
- JVM 内存：线程私有 PC、虚拟机栈、本地方法栈；共享堆、方法区。
- 类加载：加载、验证、准备、解析、初始化；双亲委派先父后子。
- MySQL 索引用 B+ 树，聚簇索引存整行，二级索引存主键。
- 事务 ACID，隔离级别四种，MySQL 默认可重复读。
- 泛型擦除，PECS：读 extends，写 super。
